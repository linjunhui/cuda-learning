# Vector Addition 项目总结

## 项目定位

这是一个**入门级项目**，主要学习目标：
1. **PyTorch 扩展绑定**：如何将 CUDA kernel 通过 PyTorch C++ 扩展暴露给 Python
2. **Benchmark 框架**：如何使用 LeetGPU 的测试和性能评估框架
3. **基础 CUDA Kernel**：编写最简单的 CUDA kernel，理解线程索引和内存访问

## 项目概述

这是一个基础的 CUDA 向量加法实现，作为学习 PyTorch 扩展和 Benchmark 框架的入门项目。

## 核心实现

### 1. CUDA Kernel (`vector_add`)

```cuda
__global__ void vector_add(float *vector_a, float *vector_b, float *output, const int N)
```

**功能**：实现两个向量的逐元素加法

**关键点**：
- 使用全局线程索引：`global_idx = blockIdx.x * blockDim.x + threadIdx.x`
- 边界检查：`if(global_idx < N)` 防止越界访问
- 逐元素计算：`output[global_idx] = vector_a[global_idx] + vector_b[global_idx]`

### 2. Kernel 启动函数 (`launch_vector_add_kernel`)

```cpp
void launch_vector_add_kernel(torch::Tensor vector_a, torch::Tensor vector_b, torch::Tensor output, const int N)
```

**功能**：配置并启动 CUDA kernel

**关键点**：
- **Block 大小**：`block_size = 64`（每个 block 64 个线程）
- **Grid 大小**：`grid_size = (N + block_size - 1) / block_size`（向上取整）
- **内存访问**：使用 `data_ptr<float>()` 获取 PyTorch Tensor 的原始指针

### 3. PyTorch 扩展绑定

```cpp
PYBIND11_MODULE(TORCH_EXTENSION_NAME, m) {
    m.def("vector_add", &launch_vector_add_kernel, "Vector Add");
}
```

**功能**：将 C++ 函数暴露给 Python

## 重要注意事项

### ⚠️ 返回类型问题

**问题描述**：
如果 `launch_vector_add_kernel` 函数声明返回类型为 `torch::Tensor`，但函数体内没有 `return` 语句，会导致编译错误或运行时 "instruction illegal" 报错。

**原因分析**：
1. **函数签名不匹配**：声明返回 `torch::Tensor` 但实际没有返回值，违反了 C++ 函数契约
2. **调用约定问题**：调用者期望接收返回值，但函数没有返回，导致栈/寄存器状态不一致
3. **编译器优化**：编译器可能基于返回类型进行优化，没有返回值会导致未定义行为

**正确做法**：
```cpp
// ✅ 正确：如果不需要返回值，声明为 void
void launch_vector_add_kernel(torch::Tensor vector_a, torch::Tensor vector_b, torch::Tensor output, const int N) {
    // ... kernel 启动代码
    // 不需要 return 语句
}

// ✅ 或者：如果需要返回 Tensor，必须返回
torch::Tensor launch_vector_add_kernel(torch::Tensor vector_a, torch::Tensor vector_b, const int N) {
    auto output = torch::empty_like(vector_a);
    // ... kernel 启动代码
    return output;  // 必须返回
}
```

**当前实现**：
- 使用 `void` 返回类型 ✅
- `output` 作为参数传入，通过 in-place 修改
- 这是合理的实现方式，因为 PyTorch 支持 in-place 操作

## 核心学习内容

### 1. PyTorch 扩展绑定 ⭐ 重点

**学习目标**：理解如何将 C++/CUDA 代码集成到 PyTorch 中

**关键知识点**：

#### 1.1 模块定义
```cpp
PYBIND11_MODULE(TORCH_EXTENSION_NAME, m) {
    m.def("vector_add", &launch_vector_add_kernel, "Vector Add");
}
```
- `TORCH_EXTENSION_NAME`：自动定义的模块名（通常来自 `setup.py`）
- `m.def()`：定义 Python 可调用的函数
- 第一个参数：Python 函数名
- 第二个参数：C++ 函数指针
- 第三个参数：函数文档字符串

#### 1.2 Tensor 类型转换
```cpp
torch::Tensor vector_a  // PyTorch Tensor 类型
vector_a.data_ptr<float>()  // 获取原始指针
```
- `torch::Tensor`：PyTorch 的 C++ Tensor 类型
- `data_ptr<T>()`：获取指定类型的原始指针（需要确保类型匹配）

#### 1.3 函数签名
- 参数类型：使用 `torch::Tensor` 接收 Python 传入的 Tensor
- 返回类型：`void` 表示无返回值（in-place 操作）或 `torch::Tensor` 返回新 Tensor

### 3. 基础 CUDA Kernel

**学习目标**：理解 CUDA kernel 的基本结构

**关键知识点**：

#### 3.1 Kernel 定义
```cuda
__global__ void vector_add(float *vector_a, float *vector_b, float *output, const int N)
```
- `__global__`：修饰符，表示在主机端调用、设备端执行的函数
- 参数：设备端指针（通过 `cudaMalloc` 或 PyTorch 管理的内存）

#### 3.2 线程索引
```cuda
unsigned int global_idx = blockIdx.x * blockDim.x + threadIdx.x;
```
- `blockIdx.x`：当前 block 在 grid 中的索引
- `blockDim.x`：每个 block 的线程数
- `threadIdx.x`：当前线程在 block 中的索引
- `global_idx`：全局线程索引（0 到 N-1）

#### 3.3 边界检查
```cuda
if(global_idx < N) {
    output[global_idx] = vector_a[global_idx] + vector_b[global_idx];
}
```
- 必须检查边界，因为 grid 大小可能向上取整，导致线程数 > N

#### 3.4 Kernel 启动
```cpp
int block_size = 64;
int grid_size = (N + block_size - 1) / block_size;
vector_add<<<grid_size, block_size>>>(...);
```
- `<<<grid_size, block_size>>>`：CUDA kernel 启动语法
- Grid 大小向上取整：`(N + block_size - 1) / block_size`

## 常见问题与注意事项

### ⚠️ 返回类型问题

**问题**：如果函数声明返回 `torch::Tensor` 但没有 `return` 语句，会导致 "instruction illegal" 错误。

**原因**：
- 函数签名不匹配：声明返回类型但实际没有返回值
- 调用约定问题：调用者期望接收返回值，但函数没有返回
- 编译器优化：基于返回类型的优化导致未定义行为

**解决方案**：
```cpp
// ✅ 方案1：使用 void（当前实现）
void launch_vector_add_kernel(..., torch::Tensor output, ...) {
    // output 作为参数传入，in-place 修改
}

// ✅ 方案2：返回 Tensor
torch::Tensor launch_vector_add_kernel(...) {
    auto output = torch::empty_like(vector_a);
    // ... kernel 启动
    return output;  // 必须返回
}
```

### ⚠️ 内存管理

- PyTorch Tensor 的内存由 PyTorch 自动管理
- 使用 `data_ptr<T>()` 获取原始指针时，确保类型匹配
- 确保 Tensor 在 GPU 上（`.cuda()` 或 `device='cuda'`）

### ⚠️ 同步问题

- Kernel 启动是异步的，如果需要等待完成，使用 `cudaDeviceSynchronize()`
- 在 Benchmark 框架中，通常会自动处理同步
