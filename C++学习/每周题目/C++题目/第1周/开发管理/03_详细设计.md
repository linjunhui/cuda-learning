## 1. 数据结构设计

### 1.1 BlockHeader

**设计目的**：在每块内存头部存放最少元数据，用于空闲链表串联，并支持「用户指针 ↔ 块头」的转换。

```cpp
struct BlockHeader {
    BlockHeader* next;  // 指向下一个空闲块
};
```

| 设计点 | 目的 | 理由 |
|--------|------|------|
| 仅含 `next` | 最小化 header 开销 | 固定大小池中块大小由池维护，不必在 header 存 size；单向链表无需 prev |
| 位于 block 起始 | 便于 ptr↔header 转换 | 用户 ptr = (char*)header + sizeof(Header)；header = (Header*)((char*)ptr - sizeof(Header)) |
| 用 struct 非 class | next 需被池直接访问 | 池要读写 next 维护 free_list，必须为 public |
| 用户可用空间 | block_size - sizeof(BlockHeader) | header 占用块内前若干字节，剩余部分给用户 |
| 内存对齐 | alignof(BlockHeader) 或 std::max_align_t | 保证用户数据区可存任意类型；对齐计算在池的 actual_block_size 中体现 |

**可选扩展（非本期必须）**：magic 校验、get_header_from_user_ptr、calculate_aligned_block_size 等工具函数，可按需在实现时补充。

### 1.2 FixedSizePool 成员
| 成员 | 类型 | 目的 | 理由 |
|------|------|------|------|
| memory_block_ | void* | 持有整块预分配内存 | 构造时一次分配，析构时一次释放，避免碎片 |
| block_size_ | size_t | 记录单块大小（含 header）| 初始化时计算并保存，分配时用于定位下一个块 |
| block_count_ | size_t | 记录块数量 | 初始化、reset、耗尽判断均需 |
| free_list_ | BlockHeader* | 空闲链表头 | 分配取头、释放插头，O(1) |
| mutex_ | std::mutex | 保护 free_list 操作 | 多线程并发 alloc/dealloc 必须加锁 |

## 2. 接口详细定义

### 2.1 构造与析构
```cpp
explicit FixedSizePool(size_t block_size, size_t block_count);
~FixedSizePool();
FixedSizePool(const FixedSizePool&) = delete;
FixedSizePool& operator=(const FixedSizePool&) = delete;
```

| 设计 | 目的 | 理由 |
|------|------|------|
| explicit 构造 | 避免隐式转换 | 防止误写 `FixedSizePool p = 64;` 导致难以发现的错误 |
| 析构释放 memory_block_ |  RAII | 池持有一块内存，析构时必须释放，避免泄漏 |
| 禁拷贝 | 避免双重释放 | 拷贝池会共享 memory_block_，两对象析构时会 double-free；移动可后续按需支持 |

### 2.2 核心接口
```cpp
void* allocate();           // 返回 nullptr 表示失败
void deallocate(void* ptr); // ptr 必须为本池 allocate 的地址
void reset();               // 将所有块回收至 free_list
```

（目的与理由见 [02_方案设计](02_方案设计.md) 第 3 节。）

### 2.3 查询接口
```cpp
size_t get_block_size() const;
size_t get_block_count() const;
size_t get_free_count() const;  // 可选
```

**目的**：供调用方和测试获取池配置及状态；`get_free_count` 用于监控或调试，非必须。

## 3. 关键算法

### 3.1 初始化
**目的**：预分配连续内存，并将所有块串成初始空闲链表。

| 步骤 | 目的 | 说明 |
|------|------|------|
| 1. align_up(block_size + sizeof(BlockHeader)) | 保证对齐 | 用户数据区需满足通用类型对齐，避免未对齐访问 |
| 2. operator new(actual_block_size * block_count) | 一次申请整块 | 减少系统调用，内存局部性更好 |
| 3. 遍历 block 串成 free_list | 建立空闲链 | 从首块起，每个 block 的 next 指向下一块，末块 next=nullptr |

### 3.2 allocate
**目的**：从 free_list 取出一块，返回用户可写地址。

| 步骤 | 目的 | 说明 |
|------|------|------|
| lock/unlock | 线程安全 | 取块和修改 free_list 必须是原子操作 |
| free_list_==nullptr→return nullptr | 耗尽处理 | 明确失败语义，不抛异常 |
| return (char*)block + sizeof(BlockHeader) | 返回用户区域 | 用户不应看到 header，只拿到数据区指针 |

### 3.3 deallocate
**目的**：将块归还 free_list，供后续 allocate 复用。

| 步骤 | 目的 | 说明 |
|------|------|------|
| ptr→block: (BlockHeader*)((char*)ptr - sizeof(BlockHeader)) | 定位 header | 用户只持有数据区 ptr，需回推得到 header 才能挂链 |
| 可选校验 ptr 属于本池 | 防御错误释放 | 可后续加 magic 或范围检查 |
| block->next=free_list_; free_list_=block | 头插归还 | 头插 O(1)，无需遍历 |

### 3.4 reset
**目的**：一次性回收所有已分配块，无需用户逐个 deallocate。

| 步骤 | 目的 | 说明 |
|------|------|------|
| 同初始化的 free_list 重建 | 全部回池 | 遍历 memory_block_ 内各 block，重新串成一条链；reset 后此前 allocate 的 ptr 全部失效 |

## 5. 异常与错误处理

| 场景 | 行为 | 目的与理由 |
|------|------|------------|
| allocate 耗尽 | 返回 nullptr | 调用方可判断失败并处理；不抛异常，与 C 风格 allocator 一致 |
| deallocate(nullptr) | 不操作（no-op）| 避免崩溃，符合「释放空指针无害」的惯例 |
| deallocate 非法 ptr | 未定义行为或断言 | 非法 ptr 会导致链表破坏；Debug 下用断言及早发现，Release 下不额外检查以保性能 |
