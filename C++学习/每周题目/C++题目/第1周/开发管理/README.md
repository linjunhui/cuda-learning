## 角色职责说明

> 学习阶段可一人扮演多角色，但应明确区分各角色的职责边界，以理解完整的软件工程流程。

| 角色 | 全称 | 核心职责 |
|------|------|----------|
| **BA** | Business Analyst 业务分析师 | 收集原始需求；澄清模糊、歧义、不可量化的描述；产出可验收的需求规格（功能/非功能）。回答「做什么」。 |
| **SA** | Solution Architect 方案架构师 | 将需求转化为技术方案；确定架构、模块划分、技术选型、分阶段策略；评估风险。回答「怎么做（宏观）」。 |
| **SD** | Software Designer 软件设计师 | 将方案细化为可编码的规格；定义接口、数据结构、算法伪代码。回答「怎么做（微观）」。 |
| **DEV** | Developer 开发工程师 | 按详细设计编写代码；遵循编码规范；完成构建与自测。产出可编译、可运行的实现。 |
| **QA** | Quality Assurance 质量保障 | 设计测试用例；执行测试；判定是否达到质量门禁。保障功能正确、无泄漏、无严重缺陷。 |
| **RM** | Release Manager 发布经理 | 组织交付物；完成发布检查；管理版本与文档。确保产物的完整性和可复用性。 |

## 使用说明

1. **按顺序推进**：每阶段完成评审后再进入下一阶段
2. **可追溯**：每个阶段的输出作为下一阶段的输入，保持前后一致
3. **迭代调整**：若发现前期问题，可回溯修改并同步更新相关文档
