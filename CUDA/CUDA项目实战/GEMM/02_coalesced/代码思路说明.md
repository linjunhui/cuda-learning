# Coalesced GEMM 代码思路说明

## 1. 概述

本项目实现了一个使用**合并访存（Coalesced Memory Access）**和**共享内存（Shared Memory）**优化的CUDA矩阵乘法核函数。这是GEMM（General Matrix Multiplication）优化的基础版本，通过合理的内存访问模式和数据重用来提升性能。

## 2. 矩阵乘法问题定义

给定两个矩阵：
- **A**: M × N 矩阵
- **B**: N × K 矩阵

计算：
- **C = A × B**，其中 C 是 M × K 矩阵

矩阵乘法的计算公式：
```
C[m][k] = Σ(A[m][n] * B[n][k])  for n = 0 to N-1
```

## 3. 核心优化思路

### 3.1 分块（Tiling）策略

**问题**：直接计算时，每个线程需要访问全局内存中的大量数据，导致内存带宽成为瓶颈。

**解决方案**：将大矩阵分成小的块（Tile），每个线程块（Block）负责计算结果矩阵C的一个子块。

- **Tile大小**：32 × 32（`TILE_SIZE = 32`）
- **线程块配置**：每个Block包含 32 × 32 = 1024 个线程
- **网格配置**：根据输出矩阵C的维度(M × K)动态计算Block数量

### 3.2 共享内存使用

**目的**：减少全局内存访问，提高数据重用率。

**实现**：
- `S_A[TILE_SIZE][TILE_SIZE]`：存储矩阵A的一个Tile
- `S_B[TILE_SIZE][PADDED_SIZE]`：存储矩阵B的一个Tile（带填充以避免bank conflict）

**优势**：
- 共享内存访问速度比全局内存快得多
- 多个线程可以共享同一份数据，减少重复读取

### 3.3 合并访存（Coalesced Memory Access）

**关键点**：确保同一warp内的线程访问连续的内存地址。

**实现方式**：

1. **矩阵A的加载**：
   ```cuda
   S_A[tid_y][tid_x] = A[(m_base + tid_y) * N + n_base + tid_x];
   ```
   - 同一行的线程（相同的`tid_y`）访问连续的内存地址
   - 满足合并访存条件

2. **矩阵B的加载**：
   ```cuda
   S_B[tid_y][tid_x] = B[B_n * K + B_k];
   ```
   - 需要转置访问模式以确保合并访存
   - 通过调整索引实现连续访问

## 4. 核函数详细解析

### 4.1 线程索引计算

```cuda
int tid_x = threadIdx.x;  // 线程在Block内的x坐标 (0-31)
int tid_y = threadIdx.y;  // 线程在Block内的y坐标 (0-31)

int m = blockDim.y * blockIdx.y + tid_y;  // 全局行索引
int k = blockDim.x * blockIdx.x + tid_x;  // 全局列索引

int m_base = blockDim.y * blockIdx.y;  // Block负责的行的起始位置
int k_base = blockDim.x * blockIdx.x;  // Block负责的列的起始位置
```

**说明**：
- 每个线程负责计算结果矩阵C中的一个元素 `C[m][k]`
- `m_base`和`k_base`定义了当前Block负责计算的子矩阵范围

### 4.2 分块循环

```cuda
int TILE_NUM = (N + TILE_SIZE - 1) / TILE_SIZE;  // 需要的Tile数量
float c_reg = 0.0f;  // 寄存器累加器

for(int i = 0; i < TILE_NUM; i++) {
    // 加载Tile到共享内存
    // 计算部分结果
    // 累加到寄存器
}
```

**思路**：
- 由于矩阵A的列数（N）可能很大，需要分多次处理
- 每次循环处理一个32×32的Tile
- 使用寄存器变量`c_reg`累加中间结果，避免频繁访问共享内存

### 4.3 数据加载阶段

#### 加载矩阵A的Tile

```cuda
int n_base = i * TILE_SIZE;
if(m_base + tid_y < M && n_base + tid_x < N) {
    S_A[tid_y][tid_x] = A[(m_base + tid_y) * N + n_base + tid_x];
} else {
    S_A[tid_y][tid_x] = 0.0f;  // 边界填充
}
```

**访问模式**：
- 加载A的第`m_base`到`m_base+31`行，第`n_base`到`n_base+31`列
- 同一行的线程访问连续内存，实现合并访存

#### 加载矩阵B的Tile

```cuda
int B_n = n_base + tid_x;  // B的行索引
int B_k = k_base + tid_y;  // B的列索引
if(k_base + tid_y < K && n_base + tid_x < N) {
    S_B[tid_y][tid_x] = B[B_n * K + B_k];
} else {
    S_B[tid_y][tid_x] = 0.0f;  // 边界填充
}
```

**关键点**：
- 注意B的访问模式：`B[B_n * K + B_k]`，其中`B_n`由`tid_x`控制，`B_k`由`tid_y`控制
- 这确保了同一warp内的线程访问连续内存

### 4.4 计算阶段

```cuda
__syncthreads();  // 等待所有线程完成数据加载

for(int t = 0; t < TILE_SIZE; t++) {
    c_reg += S_A[tid_y][t] * S_B[tid_x][t];
}

__syncthreads();  // 等待所有线程完成计算，准备下一轮加载
```

**计算逻辑**：
- 线程`(tid_y, tid_x)`计算：
  - 使用A的第`tid_y`行：`S_A[tid_y][t]`
  - 使用B的第`tid_x`列：`S_B[tid_x][t]`
- 注意：这里`S_B`的访问模式是`S_B[tid_x][t]`，而不是`S_B[t][tid_x]`
- 这是因为在加载时已经做了转置处理，以匹配计算需求

### 4.5 结果写回

```cuda
C[m * K + k] = c_reg;
```

- 将累加结果写回全局内存
- 每个线程只写一次，访问模式也是合并的

## 5. 内存访问模式分析

### 5.1 全局内存访问

**矩阵A**：
- 读取模式：按行访问，同一warp内的线程访问连续地址
- 访问次数：每个元素被读取 `K/TILE_SIZE` 次（被多个Block重用）

**矩阵B**：
- 读取模式：通过转置索引实现连续访问
- 访问次数：每个元素被读取 `M/TILE_SIZE` 次（被多个Block重用）

**矩阵C**：
- 写入模式：每个线程写一次，按行连续写入
- 访问次数：每个元素只写一次

### 5.2 共享内存访问

- **S_A**：每个Tile被32个线程行共享
- **S_B**：每个Tile被32个线程列共享
- 通过`__syncthreads()`确保数据一致性

## 6. 边界处理

代码中使用了条件检查来处理矩阵边界：

```cuda
if(m_base + tid_y < M && n_base + tid_x < N) {
    // 正常加载
} else {
    // 填充0
}
```

这确保了当矩阵维度不是Tile大小的整数倍时，程序仍能正确运行。

## 7. 性能优化要点总结

1. **合并访存**：确保同一warp内的线程访问连续内存地址
2. **共享内存重用**：数据加载到共享内存后，被多个线程重用
3. **寄存器累加**：使用寄存器变量累加中间结果，减少内存访问
4. **分块计算**：将大问题分解为小问题，提高缓存命中率
5. **同步控制**：使用`__syncthreads()`确保数据一致性

## 8. 与朴素实现的对比

**朴素实现**：
- 每个线程直接从全局内存读取所需数据
- 没有数据重用
- 内存访问不合并，带宽利用率低

**本实现**：
- 使用共享内存缓存数据
- 数据被多个线程重用
- 合并访存提高带宽利用率
- 性能提升：通常可达到2-10倍的加速

## 9. 进一步优化方向

1. **Bank Conflict避免**：当前实现中`S_B`使用了`PADDED_SIZE`来避免bank conflict
2. **双缓冲**：使用两个共享内存缓冲区，在计算一个Tile的同时加载下一个Tile
3. **寄存器分块**：在寄存器中缓存部分数据，进一步减少共享内存访问
4. **Warp级优化**：利用warp内的shuffle指令进行数据交换
5. **Tensor Core**：对于支持Tensor Core的GPU，可以使用专门的矩阵运算指令

## 11. 总结

本实现展示了CUDA矩阵乘法的基本优化技术：
- **分块策略**：将大矩阵分解为小Tile
- **共享内存**：缓存频繁访问的数据
- **合并访存**：优化内存访问模式

这些技术是CUDA性能优化的基础，理解这些概念对于开发高性能GPU程序至关重要。
