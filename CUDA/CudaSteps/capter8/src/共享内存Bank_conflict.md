## 💾 Shared Memory Bank Conflict 总结

在 CUDA Tiled 矩阵转置中，Bank Conflict 是一个核心优化点。它主要发生在 **数据从 Shared Memory (S) 读出，准备写入 Global Memory (B) 的阶段**。

### 1. 冲突发生的根源 (列访问)

* **读入 S (A $\to$ S):** 线程以 **行主序** 写入 $S$ ($S[t_y][t_x]$)。这种连续访问模式是 **无冲突** 的。
* **读出 S (S $\to$ B):** 线程必须从 **转置后的列** 访问 $S$ ($S[t_x][t_y]$) 以实现最终的合并写出 $B$。
* **冲突条件:** 当 Warp (32 线程) 尝试同时访问 $S$ 的同一列时，如果 Tile 尺寸 $T=32$ 且没有 Padding，访问步长恰好是 32，导致所有线程都映射到**同一个 Bank**，引发 **32-way Bank Conflict**（访问被序列化为 32 次）。

### 2. 解决方案：Padding（加 1）

* **方法:** 将共享内存数组定义为 `float S[T][T + 1]`。
* **原理:** **加 1** 改变了内存的寻址步长，从 $T$ (32) 变为 $T+1$ (33)。
    * 步长 33 **不是 Bank 数量 32 的倍数**。
    * 这使得相邻线程访问的 Bank 索引均匀跳跃 ($B_0, B_1, B_2, \ldots, B_{31}$)，从而实现 **无冲突访问**（1 周期完成）。

**简而言之：** Tiled 转置中，读入 $S$ 是安全行访问；读出 $S$ 是冲突列访问。**Padding** 是消除列访问冲突、确保 Shared Memory 阶段高效的关键。
