## 📋 操作步骤

### 第一步：在 `public/list/article.json` 中添加书籍信息

1. **打开文件**
   - 文件路径：`public/list/article.json`
   - 这是一个 JSON 数组文件，包含所有书籍的列表

2. **添加书籍对象**
   在数组末尾添加新的书籍对象，格式如下：

```json
{
  "id": "article_书籍ID",
  "name": "书籍名称",
  "description": "书籍描述",
  "category": "文章学习",
  "tags": ["标签1", "标签2"],
  "url": "书籍文件名.json",
  "length": 文章数量,
  "translateLanguage": "common",
  "language": "en",
  "cover": "/imgs/covers/封面图片.png"
}
```

**字段说明**：

| 字段 | 说明 | 必填 | 示例 |
|------|------|------|------|
| `id` | 书籍唯一标识符 | ✅ | `"article_nce1"` |
| `name` | 书籍显示名称 | ✅ | `"新概念英语1"` |
| `description` | 书籍描述 | ✅ | `"第一册《英语初阶》..."` |
| `category` | 分类 | ✅ | `"文章学习"` |
| `tags` | 标签数组 | ✅ | `["新概念英语"]` |
| `url` | JSON文件名（不含路径） | ✅ | `"NCE_1.json"` |
| `length` | 文章总数 | ✅ | `72` |
| `translateLanguage` | 翻译语言 | ✅ | `"common"` |
| `language` | 文章语言 | ✅ | `"en"` |
| `cover` | 封面图片路径 | ❌ | `"/imgs/covers/nce-1.png"` |
| `update` | 是否更新中 | ❌ | `true` |

**示例**：

```json
{
  "id": "article_mybook",
  "name": "我的英语书",
  "description": "这是一本自定义的英语学习书籍",
  "category": "文章学习",
  "tags": ["自定义", "英语学习"],
  "url": "MY_BOOK.json",
  "length": 10,
  "translateLanguage": "common",
  "language": "en",
  "cover": "/imgs/covers/mybook.png"
}
```

3. **保存文件**
   - 确保 JSON 格式正确（注意逗号、引号等）
   - 可以使用 JSON 验证工具检查格式

### 第二步：在 `public/dicts/en/article/` 创建文章 JSON 文件

1. **创建文件**
   - 文件路径：`public/dicts/en/article/书籍文件名.json`
   - 文件名必须与第一步中 `url` 字段的值一致
   - 例如：如果 `url` 是 `"MY_BOOK.json"`，则文件路径为 `public/dicts/en/article/MY_BOOK.json`

2. **文件格式**
   这是一个 JSON 数组，包含多篇文章：

```json
[
  {
    "id": "文章ID",
    "title": "文章标题",
    "titleTranslate": "译文标题",
    "text": "原文内容",
    "textTranslate": "译文内容",
    "newWords": [],
    "audioSrc": "音频文件路径",
    "audioFileId": "",
    "lrcPosition": [[开始时间, 结束时间], ...],
    "questions": [],
    "nameList": []
  }
]
```

**文章对象字段说明**：

| 字段 | 说明 | 必填 | 示例 |
|------|------|------|------|
| `id` | 文章唯一ID（6位随机字符串） | ✅ | `"E1Jt1u"` |
| `title` | 英文标题 | ✅ | `"Excuse me!"` |
| `titleTranslate` | 中文标题 | ✅ | `"对不起！"` |
| `text` | 英文正文 | ✅ | `"Excuse me! \n\nYes?"` |
| `textTranslate` | 中文译文 | ✅ | `"对不起 \n\n什么事？"` |
| `newWords` | 生词列表 | ✅ | `[]` |
| `audioSrc` | 音频文件路径 | ❌ | `"/sound/article/nce1/001.mp3"` |
| `audioFileId` | 音频文件ID（本地文件） | ❌ | `""` |
| `lrcPosition` | 音频时间轴数组 | ❌ | `[[15,16.55],[16.66,18.26]]` |
| `questions` | 问题列表 | ✅ | `[]` |
| `nameList` | 人名列表 | ✅ | `[]` |
| `textAllWords` | 所有单词列表 | ❌ | `[]` |
| `sections` | 段落数据（运行时生成） | ❌ | `[]` |

**文本格式要求**：

- **段落分隔**：使用 `\n\n`（两个换行符）分隔段落
- **句子分隔**：使用 `\n`（单个换行符）分隔句子
- **示例**：
  ```
  "text": "第一句。\n第二句。\n\n第二段第一句。\n第二段第二句。"
  ```

**完整示例**：

## ⚠️ 注意事项

1. **文章数量约束** ⚠️ **重要**
   - **每个 JSON 文件至少包含 10 篇文章**
   - 这是系统要求的最低标准，确保学习内容的丰富性
   - `article.json` 中的 `length` 字段必须 ≥ 10
   - 如果文章数量少于 10 篇，系统可能无法正常显示或使用
   - 建议每个书籍包含 20-50 篇文章，以获得更好的学习体验

2. **JSON 格式**
   - 确保所有 JSON 文件格式正确
   - 注意逗号、引号、括号的匹配
   - 可以使用在线 JSON 验证工具检查

3. **文件路径**
   - `article.json` 中的 `url` 字段必须与实际的 JSON 文件名完全一致
   - 文件必须放在 `public/dicts/en/article/` 目录下

4. **ID 唯一性**
   - 书籍 `id` 必须唯一，不能与现有书籍重复
   - 文章 `id` 建议使用 6 位随机字符串（可以使用 `nanoid(6)` 生成）
   - 同一 JSON 文件内的文章 `id` 也必须唯一

5. **文本格式**
   - 段落之间用 `\n\n` 分隔
   - 句子之间用 `\n` 分隔
   - 保持格式一致，便于系统解析

6. **音频文件**
   - 如果有音频，将文件放在 `public/sound/article/` 目录下
   - `audioSrc` 使用相对于 `public` 的路径
   - `lrcPosition` 是二维数组，格式：`[[开始秒数, 结束秒数], ...]`

7. **文章数量**
   - `article.json` 中的 `length` 字段应该等于实际文章数量
   - 如果添加或删除文章，记得更新 `length` 字段
   - **必须确保 `length` ≥ 10**

## ❓ 常见问题

**Q: 添加后看不到新书籍？**
A: 检查以下几点：
- JSON 格式是否正确
- 文件路径是否正确
- `url` 字段是否与文件名一致
- 清除浏览器缓存后重试

**Q: 文章显示不正确？**
A: 检查以下几点：
- 文本格式是否正确（段落用 `\n\n`，句子用 `\n`）
- JSON 结构是否正确
- 控制台是否有错误信息

**Q: 如何批量添加文章？**
A: 可以在 JSON 文件中一次性添加多篇文章对象，确保：
- 所有文章都在同一个数组中
- 每个文章都有唯一的 `id`
- **至少包含 10 篇文章**（系统要求）
- 更新 `article.json` 中的 `length` 字段

**Q: 为什么要求至少 10 篇文章？**
A: 这是系统的最低要求，原因包括：
- 确保学习内容的丰富性和连贯性
- 提供足够的学习材料供用户练习
- 保持数据结构的完整性和一致性
- 如果文章太少，可能影响系统的正常功能

**Q: 如果只有几篇文章怎么办？**
A: 建议：
- 继续从 `/home/jonson/cuda-learning/` 目录中提取更多内容
- 可以将一个主题拆分成多个子主题，每个子主题作为一篇文章
- 或者暂时不创建该书籍，等积累足够内容后再创建
