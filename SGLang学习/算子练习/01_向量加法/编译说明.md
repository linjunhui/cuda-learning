# 向量加法项目编译说明

本文档介绍两种编译方式：手动编译链接和CMake编译。

## 项目结构

```
01_向量加法/
├── src/
│   ├── main.cpp          # C++主机端代码
│   ├── vector_add.cu     # CUDA设备端代码（kernel实现）
│   └── vector_add.cuh    # CUDA头文件（kernel声明）
└── CMakeLists.txt        # CMake配置文件
```

## 方式一：手动编译链接

### 编译步骤

手动编译需要将CUDA代码和C++代码分开编译，然后链接在一起。

#### 1. 编译CUDA代码（生成目标文件）

```bash
nvcc -c src/vector_add.cu -o build/vector_add.o \
     -arch=sm_75 \
     -std=c++17 \
     -Xcompiler -fPIC
```

**参数说明：**
- `-c`: 只编译不链接，生成目标文件
- `-arch=sm_75`: 指定CUDA架构（根据你的GPU调整，常见值：sm_75, sm_80, sm_86, sm_89, sm_90）
- `-std=c++17`: 使用C++17标准
- `-Xcompiler -fPIC`: 生成位置无关代码，便于链接
- `-o build/vector_add.o`: 输出目标文件路径

#### 2. 编译C++代码（生成目标文件）

**注意：** 现在 `main.cpp` 只包含标准C++代码（不包含CUDA语法），可以使用 `g++` 编译。

```bash
g++ -c src/main.cpp -o build/main.o \
    -std=c++17 \
    -I/usr/local/cuda/include \
    -fPIC
```

**参数说明：**
- `-c`: 只编译不链接，生成目标文件
- `-std=c++17`: 使用C++17标准
- `-I/usr/local/cuda/include`: 包含CUDA头文件路径（根据实际CUDA安装路径调整）
- `-fPIC`: 生成位置无关代码，便于链接
- `-o build/main.o`: 输出目标文件路径

**为什么可以用g++？**
- `main.cpp` 现在只包含标准C++代码，不包含CUDA kernel调用语法 `<<<...>>>`
- `launch_kernel` 函数的实现已移到 `vector_add.cu` 文件中
- 所有CUDA相关的代码都在 `.cu` 文件中，由 `nvcc` 编译

#### 3. 链接生成可执行文件

**推荐方式：使用 `nvcc` 链接**

```bash
nvcc build/main.o build/vector_add.o -o build/bin/vector_add \
     -lcudart \
     -lcuda
```

**参数说明：**
- `build/main.o build/vector_add.o`: 链接两个目标文件
- `-lcudart`: 链接CUDA运行时库
- `-lcuda`: 链接CUDA驱动库
- `-o build/bin/vector_add`: 输出可执行文件路径

**为什么推荐用 `nvcc` 链接？**

1. **自动处理CUDA设备代码链接**
   - `nvcc` 知道如何处理CUDA设备代码（PTX、cubin等）
   - 自动处理设备代码的注册和初始化

2. **自动查找CUDA库路径**
   - `nvcc` 自动知道CUDA库的安装位置
   - 不需要手动指定 `-L/usr/local/cuda/lib64` 等路径

3. **处理CUDA运行时初始化**
   - `nvcc` 会自动链接必要的CUDA运行时初始化代码
   - 确保CUDA运行时正确初始化

4. **简化链接选项**
   - 只需指定 `-lcudart` 和 `-lcuda`，nvcc会自动处理其他细节

**替代方式：使用 `g++` 链接（不推荐）**

```bash
g++ build/main.o build/vector_add.o -o build/bin/vector_add \
    -L/usr/local/cuda/lib64 \
    -lcudart \
    -lcuda \
    -lcudart_static \
    -ldl \
    -lrt \
    -pthread
```

**为什么用 `g++` 链接更复杂？**

1. **需要手动指定库路径**
   - 必须添加 `-L/usr/local/cuda/lib64`（路径可能因安装而异）

2. **需要链接更多库**
   - 除了 `-lcudart`，可能还需要 `-lcudart_static`、`-ldl`、`-lrt`、`-pthread` 等

3. **可能缺少设备代码处理**
   - `g++` 可能无法正确处理CUDA设备代码的链接
   - 可能导致运行时错误

4. **跨平台兼容性差**
   - 不同系统的CUDA库路径可能不同
   - 需要根据环境调整链接选项

**总结：**
- ✅ **推荐使用 `nvcc` 链接**：简单、可靠、自动处理CUDA相关细节
- ⚠️ **可以用 `g++` 链接**：但需要更多配置，且可能遇到问题

### 完整编译脚本

创建 `build.sh` 脚本一键编译：

```bash
#!/bin/bash

# 创建构建目录
mkdir -p build/bin

# 编译CUDA代码
echo "编译CUDA代码..."
nvcc -c src/vector_add.cu -o build/vector_add.o \
     -arch=sm_75 \
     -std=c++17 \
     -Xcompiler -fPIC

# 编译C++代码（现在可以用g++编译）
echo "编译C++代码..."
g++ -c src/main.cpp -o build/main.o \
    -std=c++17 \
    -I/usr/local/cuda/include \
    -fPIC

# 链接
echo "链接生成可执行文件..."
nvcc build/main.o build/vector_add.o -o build/bin/vector_add \
     -lcudart \
     -lcuda

echo "编译完成！可执行文件位于: build/bin/vector_add"
```

### 运行

```bash
./build/bin/vector_add
```

## 方式二：CMake编译

### 最简CMakeLists.txt配置

创建或使用以下最简配置：

```cmake
cmake_minimum_required(VERSION 3.18)

# 项目名称和语言
project(VectorAdd LANGUAGES CXX CUDA)

# 设置C++标准
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CUDA_STANDARD 17)

# 设置输出目录
set(CMAKE_RUNTIME_OUTPUT_DIRECTORY ${CMAKE_BINARY_DIR}/bin)

# 添加可执行文件
add_executable(vector_add 
    src/main.cpp
    src/vector_add.cu
)

# 设置CUDA架构（根据你的GPU调整）
set(CMAKE_CUDA_ARCHITECTURES "75" CACHE STRING "CUDA architectures")
```

### 编译步骤

#### 1. 创建构建目录

```bash
mkdir -p build
cd build
```

#### 2. 配置CMake

```bash
cmake ..
```

如果需要指定CUDA架构：

```bash
cmake -DCMAKE_CUDA_ARCHITECTURES=75 ..
```

#### 3. 编译

```bash
make
```

或者使用CMake的构建命令：

```bash
cmake --build .
```

#### 4. 运行

```bash
./bin/vector_add
```

### 完整编译流程（一行命令）

```bash
mkdir -p build && cd build && cmake .. && make && cd ..
```

## 两种方式对比

| 特性 | 手动编译 | CMake编译 |
|------|---------|-----------|
| **复杂度** | 需要手动管理编译参数 | 自动管理，配置简单 |
| **灵活性** | 完全控制编译过程 | 通过CMake变量控制 |
| **跨平台** | 需要修改脚本 | CMake自动适配 |
| **依赖管理** | 手动指定路径 | CMake自动查找 |
| **推荐场景** | 学习理解编译过程 | 日常开发和项目构建 |

## 常见问题

### ⚠️ 错误1：`undefined reference to 'main'`

**错误信息：**
```
/usr/bin/ld: undefined reference to `main'
collect2: error: ld returned 1 exit status
```

**原因：**
编译CUDA代码时**缺少 `-c` 选项**，导致nvcc尝试链接但找不到main函数。

**错误命令：**
```bash
nvcc vector_add.cu -o vector_add.o -arch=sm_75 ...  # ❌ 缺少 -c
```

**正确命令：**
```bash
nvcc -c vector_add.cu -o vector_add.o -arch=sm_75 ...  # ✅ 添加 -c
```

**关键点：**
- `-c` 选项表示"只编译不链接"（compile only, do not link）
- 没有 `-c` 时，编译器会尝试生成可执行文件，需要找到 `main` 函数
- 分离编译时，每个源文件都需要 `-c` 选项，最后再统一链接

### ⚠️ 错误2：`expected primary-expression before '<' token`

**错误信息：**
```
main.cpp:20:16: error: expected primary-expression before '<' token
   20 |     vectorAdd<<<grid_size, block_size>>>(d_input1, d_input2, d_output, N);
      |                ^
main.cpp:20:40: error: expected primary-expression before '>' token
```

**原因：**
使用 `g++` 编译包含CUDA kernel调用语法 `<<<...>>>` 的文件。g++无法识别CUDA特有的语法。

**解决方案：**
将包含CUDA kernel调用的代码移到 `.cu` 文件中（如 `launch_kernel` 函数），这样 `main.cpp` 就只包含标准C++代码，可以用 `g++` 编译。

**代码组织建议：**
- ✅ **推荐做法**：将所有CUDA相关代码（kernel调用、设备内存管理等）放在 `.cu` 文件中
- ✅ `main.cpp` 只包含标准C++代码，可以用 `g++` 编译
- ✅ `.cu` 文件包含CUDA语法，用 `nvcc` 编译

**关键点：**
- 任何包含CUDA kernel调用 `<<<...>>>` 的文件都必须用 `nvcc` 编译
- `nvcc` 可以编译 `.cpp` 文件，并能识别CUDA语法
- 如果文件只包含标准C++代码（无CUDA语法），可以用 `g++` 编译
- **最佳实践**：将CUDA代码和C++代码分离，CUDA代码放在 `.cu` 文件中

### 1. CUDA架构如何确定？

使用以下命令查看GPU计算能力：

```bash
nvidia-smi --query-gpu=compute_cap --format=csv
```

或者运行：

```bash
/usr/local/cuda/extras/demo_suite/deviceQuery
```

### 2. CUDA路径找不到？

检查CUDA安装路径：

```bash
which nvcc
```

通常CUDA安装在 `/usr/local/cuda/`，如果不同，需要修改 `-I` 参数中的路径。

### 3. 链接错误？

确保链接了必要的CUDA库：
- `-lcudart`: CUDA运行时库
- `-lcuda`: CUDA驱动库

### 4. 分离编译问题？

如果遇到模板函数分离编译问题，确保：
- `.cu` 文件中包含模板的显式实例化（如 `template void vectorAdd<float>(...)`）
- 使用 `CUDA_SEPARABLE_COMPILATION` 属性（CMake方式）

### 5. 链接时用 `nvcc` 还是 `g++`？

**推荐使用 `nvcc` 链接，原因如下：**

1. **自动处理CUDA设备代码**
   - CUDA设备代码（kernel函数）需要特殊的链接处理
   - `nvcc` 会自动处理PTX代码、设备函数注册等

2. **自动查找CUDA库**
   - `nvcc` 知道CUDA库的安装位置，无需手动指定 `-L` 路径
   - 自动链接必要的CUDA运行时库

3. **简化链接命令**
   - 只需 `nvcc ... -lcudart -lcuda` 即可
   - 用 `g++` 需要更多参数和路径配置

4. **更好的兼容性**
   - `nvcc` 会根据CUDA版本自动选择正确的库
   - 跨平台和跨版本兼容性更好

**技术细节：**
- `nvcc` 在链接时会调用底层的 `g++` 或 `clang++`，但会添加必要的CUDA相关选项
- 使用 `nvcc --verbose` 可以看到实际调用的链接命令
- 虽然理论上可以用 `g++` 链接，但需要手动配置很多选项，容易出错

## 调试选项

### Debug模式编译

**手动编译：**
```bash
nvcc -c src/vector_add.cu -o build/vector_add.o -g -G ...
g++ -c src/main.cpp -o build/main.o -g ...
```

**CMake编译：**
```bash
cmake -DCMAKE_BUILD_TYPE=Debug ..
make
```

### Release模式编译

**手动编译：**
```bash
nvcc -c src/vector_add.cu -o build/vector_add.o -O3 ...
g++ -c src/main.cpp -o build/main.o -O3 ...
```

**CMake编译：**
```bash
cmake -DCMAKE_BUILD_TYPE=Release ..
make
```
