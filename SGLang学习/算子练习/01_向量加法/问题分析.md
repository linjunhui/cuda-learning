# 链接错误问题分析

## 错误信息

```
/usr/bin/ld: CMakeFiles/vector_add.dir/src/main.cpp.o: in function `void launch_kernel<float>(float*, float*, float*, long, long)':
/home/jonson/cuda-learning/SGLang学习/算子练习/01_向量加法/src/main.cpp:16:(.text._Z13launch_kernelIfEvPT_S1_S1_ll[_Z13launch_kernelIfEvPT_S1_S1_ll]+0xae): undefined reference to `void vectorAdd<float>(float*, float*, float*, long)'
collect2: error: ld returned 1 exit status
```

## 问题根源

### 1. 文件结构分析

- **vector_add.cuh**：只有模板函数**声明**
  ```cpp
  template<typename T>
  __global__ void vectorAdd(T *input1, T *input2, T *output, int64_t N);
  ```

- **vector_add.cu**：有模板函数**实现**
  ```cpp
  template <typename T>
  __global__ void vectorAdd(T *input1, T* input2, T *output, int64_t N) {
      // 实现代码
  }
  ```

- **main.cpp**：调用了 `vectorAdd<float>`
  ```cpp
  vectorAdd(d_input1, d_input2, d_output, N);  // 第 16 行
  ```

### 2. 编译过程分析

#### main.cpp 的编译（由 g++ 编译）
1. 包含 `vector_add.cuh`，看到模板函数声明
2. 在 `launch_kernel<float>` 中调用 `vectorAdd<float>`
3. 生成对 `vectorAdd<float>` 的调用符号
4. **但看不到实现**（实现在 `.cu` 文件中）

#### vector_add.cu 的编译（由 nvcc 编译）
1. 包含模板函数的实现
2. **但模板没有被实例化**
3. 没有生成 `vectorAdd<float>` 的具体符号

### 3. 链接阶段

- 链接器需要找到 `vectorAdd<float>` 的实现
- `vector_add.cu` 中只有模板定义，没有实例化
- 因此找不到符号 → **链接错误**

## 核心问题

**模板函数分离编译问题**：

- 模板函数需要在编译时实例化
- 当前实现放在 `.cu` 中，但没有显式实例化
- `main.cpp` 是 `.cpp` 文件，无法看到 `.cu` 中的模板实现
- 链接时找不到 `vectorAdd<float>` 的符号

## 解决方案

### 方案1：在 .cuh 中提供实现（推荐，最简单）

**优点**：
- 最简单直接
- 符合模板函数的常见做法
- 支持任意类型，无需维护实例化列表

**实现方式**：
将 `vector_add.cu` 中的实现移到 `vector_add.cuh` 中

```cpp
// vector_add.cuh
template<typename T>
__global__ void vectorAdd(T *input1, T *input2, T *output, int64_t N) {
    int tid = threadIdx.x + blockDim.x * blockIdx.x;
    if(tid < N) {
        output[tid] = input1[tid] + input2[tid];
    }
}
```

### 方案2：在 .cu 中显式实例化

**优点**：
- 头文件更简洁
- 可以控制哪些类型被实例化

**实现方式**：
在 `vector_add.cu` 末尾添加显式实例化：

```cpp
// vector_add.cu
#include "vector_add.cuh"

template <typename T>
__global__ void vectorAdd(T *input1, T* input2, T *output, int64_t N) {
    // 实现代码
}

// 显式实例化常用的类型
template __global__ void vectorAdd<float>(float*, float*, float*, int64_t);
template __global__ void vectorAdd<double>(double*, double*, double*, int64_t);
template __global__ void vectorAdd<int>(int*, int*, int*, int64_t);
```

### 方案3：将 main.cpp 改为 main.cu

**优点**：
- 让 nvcc 处理模板实例化
- 可以保持实现和声明分离

**实现方式**：
1. 将 `main.cpp` 重命名为 `main.cu`
2. 修改 `CMakeLists.txt` 中的源文件列表

## 其他发现的问题

### 问题1：类型大小计算错误

在 `main.cpp` 第 29 行：
```cpp
int64_t M_SIZE = sizeof(int) * N;  // ❌ 错误
```

应该是：
```cpp
int64_t M_SIZE = sizeof(float) * N;  // ✅ 正确
```

因为使用的是 `float` 类型，但计算大小时用的是 `sizeof(int)`。

### 问题2：launch_kernel 模板参数类型不一致

在 `main.cpp` 第 6 行：
```cpp
template<typename T>
void launch_kernel(T *h_input1, T *h_input2, T *h_output, int64_t N, int64_t M_SIZE) {
    float *d_input1, *d_input2, *d_output;  // ❌ 硬编码为 float
```

应该使用模板类型：
```cpp
template<typename T>
void launch_kernel(T *h_input1, T *h_input2, T *h_output, int64_t N, int64_t M_SIZE) {
    T *d_input1, *d_input2, *d_output;  // ✅ 使用模板类型
```

## 推荐解决方案

**推荐使用方案1**（在 `.cuh` 中提供实现），因为：
1. 最简单直接
2. 符合模板函数的常见做法
3. 支持任意类型，无需维护实例化列表
4. 对于学习项目，代码可读性更重要

## 总结

这是一个典型的**模板函数分离编译问题**。模板函数需要在编译时实例化，当前实现放在 `.cu` 中但没有显式实例化，导致链接时找不到符号。

解决方法是：
- 要么在头文件中提供实现（推荐）
- 要么在 `.cu` 中显式实例化
- 要么将调用方改为 `.cu` 文件
