## 项目概述

### 项目简介

本项目是一个基于 CUDA 的 Flash Attention 实现，专门用于学习 CUDA 编程。项目使用 **Tensor Core** 和纯 **MMA (Matrix Multiply-Accumulate) PTX 指令**来实现 Flash Attention-2 算法，展示了如何从零开始编写高性能的注意力机制内核。

### 核心目标

- **教育性**：作为 CUDA 编程和 GPU 内核优化的学习资源
- **性能优化**：在小规模注意力计算（B≤4, H≤48, SeqLen≤8192, D≤64）上实现优于官方 FA2/SDPA 的性能
- **技术探索**：探索多种内存优化和计算优化策略

### 技术栈

- **CUDA**：>= 12.0（推荐 12.5）
- **PyTorch**：>= 2.0（推荐 2.5.1）
- **Tensor Core**：使用 m16n8k16 MMA 指令
- **Python**：用于测试和基准测试

## 核心算法与实现

### Flash Attention 算法

Flash Attention 是一种内存高效的注意力机制实现，通过以下方式减少内存访问：

1. **分块计算（Tiling）**：将 Q、K、V 矩阵分块处理
2. **在线 Softmax**：在计算过程中动态更新 softmax 统计量
3. **重计算（Recomputation）**：不存储完整的注意力矩阵，需要时重新计算

### 算法流程

```
对于每个 Q 块 [Br, d]：
    初始化 m_prev = -inf, l_prev = 0, o_prev = 0
    
    对于每个 K/V 块 [Bc, d]：
        # 计算 Q@K^T
        S = Q_block @ K_block^T  # [Br, Bc]
        S = S * scale
        
        # 在线 Softmax
        m_curr = max(S, dim=-1)
        p = exp(S - m_curr)
        l_curr = sum(p, dim=-1)
        
        # 更新输出
        alpha = exp(m_prev - m_curr)
        o_prev = o_prev * alpha + p @ V_block
        
        # 更新统计量
        l_new = alpha * l_prev + l_curr
        o_prev = o_prev / l_new
        
        m_prev = m_curr
        l_prev = l_new
    
    输出 o_prev
```

## 技术特性

### 1. Tensor Core 使用

项目使用 **m16n8k16** MMA 指令，这是 NVIDIA Tensor Core 的基本计算单元：

- **m16**：每个 MMA 操作处理 16 行
- **n8**：每个 MMA 操作处理 8 列
- **k16**：每个 MMA 操作处理 16 个元素的内积

### 2. 内存优化技术

#### Pack LDST（打包加载/存储）
- 使用 128 位向量化加载/存储（`float4`）
- 减少内存事务数量，提高带宽利用率

#### Copy Async（异步拷贝）
- `cp.async.cg`：全局缓存（L2）
- `cp.async.ca`：全缓存（L1 + L2）
- 支持多阶段流水线，隐藏内存延迟

#### Shared Memory Swizzle
- 重新排列共享内存访问模式
- 减少 bank conflicts
- 提高内存访问效率

### 3. 多阶段流水线（Multi-Stage）

支持 1 阶段和 2 阶段流水线：

- **Stage 1**：单缓冲，内存占用更小
- **Stage 2**：双缓冲，更好的计算/内存重叠

### 4. 精度支持

- **F16F16F16F16**：标准半精度
- **F32F16F16F32**：F32 累加精度，提高数值稳定性

## 性能优化策略

### 策略 1：Split KV（分割 KV）

**特点**：
- 在所有 MMA（Warp）之间分割 QKV
- 使用简单的矩阵乘法（MMA）和 Warp 分块策略

**性能**：较慢，主要用于性能对比

**实现文件**：`mma/basic/flash_attn_mma_split_kv.cu`

### 策略 2：Split Q（分割 Q）⭐

**特点**：
- 在 MMA（Warp）之间分割 Q
- 所有 MMA（Warp）共享访问 KV
- 减少通过 smem 和 warp shuffle 的通信

**性能**：比 Split KV 快约 32-44%

**布局示例**（Br=64, Bc=64, 4 warps）：
```
|   64x64   |      warp_KV 0       |
| warp_QP 0 | MMA 0 ... MMA 0 (x8) |
| warp_QP 1 | MMA 1 ... MMA 1 (x8) |
| warp_QP 2 | MMA 2 ... MMA 2 (x8) |
| warp_QP 3 | MMA 3 ... MMA 3 (x8) |
```

**实现文件**：`mma/basic/flash_attn_mma_split_q.cu`

### 策略 3：Split Q + Shared KV SMEM（共享 KV 共享内存）

**特点**：
- K 和 V 共享相同的共享内存
- 提高块占用率

**内存优化**：相比 FA2，共享内存使用减少 **1/2**

**实现文件**：`mma/basic/flash_attn_mma_share_kv.cu`

### 策略 4：Split Q + Fully Shared QKV SMEM（完全共享 QKV）⭐⭐

**特点**：
- Q、K、V 完全共享相同的共享内存
- Q 预取 s2r（shared-to-register）
- 减少 Q 的 SMEM IO 访问

**内存优化**：相比 FA2，共享内存使用减少 **1/4**

**性能提升**：在 RTX 3080 Laptop 上，D=64 时达到 **55 TFLOPS**，比 FA2 快约 **1.5x**

**实现文件**：`mma/basic/flash_attn_mma_share_qkv.cu`

### 策略 5：Split Q + QK Fine-grained Tiling（QK 细粒度分块）

**特点**：
- 在 MMA 级别对 Q 和 K 进行细粒度分块
- Q 和 K 的 SRAM 使用量为常数：`64 * kMmaAtomK`
- V 的 SRAM 复杂度为 `O(kMmaAtomK * d)`
- 总体 SRAM 复杂度：`O(kMmaAtomK * d)`

**优势**：允许扩展 D（头维度）到 **1024**

**实现文件**：`mma/basic/flash_attn_mma_tiling_qk.cu`

### 策略 6：Split Q + Fully QKV Fine-grained Tiling（完全 QKV 细粒度分块）⭐⭐⭐

**特点**：
- 对所有 Q@K^T 和 P@V 在 MMA 级别进行细粒度分块
- Q、K、V 的 SRAM 使用量为常数：`Br * 16` 或 `Bc * 16`
- 总体 SRAM 复杂度：`O(Br * 16)`，接近 `O(1)`

**优势**：
- 在 d >= 512 时，性能优于 SDPA（无论是否使用 MMA Acc F32）
- 在 NVIDIA L20 上，D=512 时达到 **104 TFLOPS**，比 SDPA 快约 **1.8x**

**实现文件**：`mma/basic/flash_attn_mma_tiling_qkv.cu`

### Swizzle 优化

Swizzle 优化应用于共享内存访问模式，减少 bank conflicts：

- **swizzle_q**：仅对 Q 应用 swizzle
- **swizzle_qk**：对 Q 和 K 应用 swizzle
- **swizzle_qkv**：对 Q、K、V 全部应用 swizzle

**实现位置**：`mma/swizzle/` 目录

## 代码组织

### 内核函数模板参数

每个内核函数都使用模板参数进行配置：

```cpp
template <
    const int kHeadDim,          // 头维度：32, 64, 128, 512, ...
    const int kMmaAtomM,         // MMA Atom M：16
    const int kMmaAtomN,         // MMA Atom N：8
    const int kMmaAtomK,         // MMA Atom K：16
    const int kMmaTileSeqLenQ,   // Q 序列长度分块：4
    const int kMmaTileSeqLenK,   // K 序列长度分块：1
    const int kMmaTileSeqLenP,   // P 序列长度分块：4
    const int kMmaTileHeadDimV,  // V 头维度分块：1
    const int kWarpTileSeqLenQ,  // Warp Q 序列长度分块：1
    const int kWarpTileSeqLenK,  // Warp K 序列长度分块：8
    const int kWarpTileSeqLenP,  // Warp P 序列长度分块：1
    const int kWarpTileHeadDimV, // Warp V 头维度分块：8
    const int kStage,            // 流水线阶段数：1 或 2
    const int kPad               // 填充：0, 8, 16
>
```

### 关键计算尺寸

```cpp
constexpr int Br = kMmaAtomM * kMmaTileSeqLenQ * kWarpTileSeqLenQ;  // 16*4*1=64
constexpr int Bc = kMmaAtomN * kMmaTileSeqLenK * kWarpTileSeqLenK;  // 8*1*8=64
constexpr int kNumThreads = WARP_SIZE * kMmaTileSeqLenQ * kMmaTileSeqLenK;  // 32*4*1=128
```

### 共享内存布局

```cpp
extern __shared__ half smem[];
constexpr int Q_tile_size = Br * (kHeadDim + kPad);
constexpr int KV_tile_size = Bc * (kHeadDim + kPad);

half *Q_tile_smem = smem;
half *K_tile_smem = Q_tile_smem + Q_tile_size;
half *V_tile_smem = K_tile_smem + kStage * KV_tile_size;
```

### 工具函数（utils.h）

`utils.h` 提供了关键的 CUDA 工具宏：

#### 内存操作宏
- `LDST128BITS`：128 位向量化加载/存储
- `CP_ASYNC_CG`：全局缓存异步拷贝
- `CP_ASYNC_CA`：全缓存异步拷贝

#### Matrix 操作宏
- `LDMATRIX_X1/X2/X4`：从共享内存加载矩阵
- `LDMATRIX_X1_T/X2_T/X4_T`：转置加载
- `STMATRIX_X1/X2/X4`：存储矩阵到共享内存（sm_90+）

#### Warp 操作
- `__shfl_sync`：warp shuffle
- `__reduce_max_sync`：warp 内最大值归约
- `__reduce_sum_sync`：warp 内求和归约

## 技术细节

### 1. MMA 指令使用

#### m16n8k16 MMA 指令

```cpp
// 使用 wmma API 或 PTX 内联汇编
using namespace nvcuda::wmma;

// 加载矩阵到寄存器
fragment<matrix_a, 16, 8, 16, half, row_major> frag_q;
fragment<matrix_b, 16, 8, 16, half, col_major> frag_k;
fragment<accumulator, 16, 8, 16, float> frag_acc;

// 执行矩阵乘法
load_matrix_sync(frag_q, q_smem_ptr, ...);
load_matrix_sync(frag_k, k_smem_ptr, ...);
mma_sync(frag_acc, frag_q, frag_k, frag_acc);
```

#### PTX 内联汇编（ldmatrix）

```cpp
// 从共享内存加载矩阵（使用 ldmatrix）
#define LDMATRIX_X4(R0, R1, R2, R3, addr) \
  asm volatile( \
    "ldmatrix.sync.aligned.x4.m8n8.shared.b16 {%0, %1, %2, %3}, [%4];\n" \
    : "=r"(R0), "=r"(R1), "=r"(R2), "=r"(R3) \
    : "r"(addr))
```

### 2. 在线 Softmax 实现

```cpp
// 计算当前块的最大值
float m_curr = -INFINITY;
for (int i = 0; i < Bc; i++) {
    m_curr = fmaxf(m_curr, S[i]);
}

// 计算 exp(S - m_curr) 和 sum
float l_curr = 0.0f;
for (int i = 0; i < Bc; i++) {
    float p = expf(S[i] - m_curr);
    l_curr += p;
    // 计算 p @ V
    // ...
}

// 更新输出
float alpha = expf(m_prev - m_curr);
o_prev = o_prev * alpha + pV;
l_new = alpha * l_prev + l_curr;
o_prev = o_prev / l_new;
```

### 3. 多阶段流水线

#### Stage 1（单缓冲）

```cpp
// 加载 K/V 到共享内存
cp_async_cg(K_tile_smem, K_gmem, ...);
cp_async_commit_group();
cp_async_wait_all();

// 计算
compute_QK();
compute_PV();
```

#### Stage 2（双缓冲）

```cpp
// 阶段 1：加载第一个 K/V 块
cp_async_cg(K_tile_smem[0], K_gmem, ...);
cp_async_commit_group();
cp_async_wait_all();

for (int tc = 0; tc < Tc; tc++) {
    // 阶段 2：异步加载下一个 K/V 块
    if (tc + 1 < Tc) {
        cp_async_cg(K_tile_smem[(tc+1)%2], K_gmem_next, ...);
        cp_async_commit_group();
    }
    
    // 计算当前块
    compute_QK();
    compute_PV();
    
    // 等待下一个块加载完成
    if (tc + 1 < Tc) {
        cp_async_wait_all();
    }
}
```

## 总结

### 项目亮点

1. **完整的实现**：从基础的 Split KV 到高级的 QKV Tiling，展示了 Flash Attention 的完整优化路径
